# talon-ui T4 Polish Implementation Plan

> **For agentic workers:** Execute task-by-task, one conventional commit per task, each gated (`pnpm test && pnpm typecheck && pnpm build`) — the T2/T3 discipline. Steps use checkbox (`- [ ]`) syntax.

**Goal:** T4 per spec §8: `/model` selector, `@file` + `@session` completion, OSC 9 notification + OSC 0 title (sanitized), clipboard and image paste, `/agents` + workflow cards, settings persistence, Windows. Acceptance: every feature surface ticked off one by one; Windows snapshots stable (cross-drive cwd handling).

**Architecture:** unchanged from T3 and load-bearing here. Everything renderable still arrives as a durable session event through `translateSessionEvent` → `Transcript.apply`, so a resumed screen equals the live screen. T4 adds three things that are NOT events and must therefore stay strictly outside the transcript: the terminal's title and notification bell (side effects on the terminal, driven by live state), the completion providers (they read the workspace and the session store, and produce ordinary prompt TEXT — never content), and persisted settings (durable, but user preference, never session history). The §3.10 law binds all three: **session-scoped UI state is either ephemeral or strictly derived from recorded events — it never goes to disk and never enters the session log.** Ctrl+O/Ctrl+R stay ephemeral; what T4 persists is preference (theme scheme, notification opt-out), not state.

**Tech Stack:** unchanged (TypeScript strict ESM, Node >=22.19, pnpm, `@earendil-works/pi-tui@0.84.1`, vitest 3 + v8 per-file 100%, `@xterm/headless`, dsh source-linked from `../deepseek-harness`, `highlight.js`, `saxes`). **No net-new npm dependencies.** One net-new COMPOSED dsh row: `@deepseek-ai/dsh-file-reference-local` (see ruling 2).

**Spec:** `docs/specs/2026-08-13-talon-ui-design.md` (§3.5, §3.6, §3.7, §3.9, §3.10, §4.3, §6, §8 T4 row) plus the parent archaeology `../docs/dsh-tui-module-plan.md` §E1/§E2 and `../docs/webui-talon-feature-gap.md`. dsh ground truth verified against `deepseek-harness@528c682e06` (**0.1.1-rc.1**) on 2026-08-28 — the same checkout T3 shipped against.

## Global Constraints

Everything from T2/T3 still binds, verbatim: relative imports carry `.js`; every untrusted string passes `displayText()` **before** styling (D7.8 — now including the BIDI controls T3 added); no rendered row may exceed the terminal width; committed cells construct nothing inside `render(width)`; the mount cap counts CONTENT lines, O(1) per apply; `setClearOnShrink(false)` stays and `tests/redraw.spec.ts` stays at zero wipes for the append-shaped flow; close panels via `setFocus(composerEditor)`; UI copy English with constants in the rendering file; per task `pnpm test && pnpm typecheck && pnpm build` green then one conventional commit; v8 per-file 100% with reasoned `/* v8 ignore */` only; every new checkpoint follows the three-leg closed-manifest law; every new cell class registers in `Transcript.lineCountOf`.

Two T4-specific constraints:

- **Nothing typed into the composer is content.** `@file` and `@session` insert PROMPT TEXT. The file's contents stay behind the model-facing `read` tool and the session's history stays in its own log — the completion index holds paths and titles only. This is `dsh-file-reference`'s own stated contract and talon must not widen it.
- **A terminal side effect is not a render.** The title and the notification bell are written through the `Terminal` seam, never through a component, so no cell can ever depend on them and a headless snapshot observes them as header fields (`title "…"`), not as rows.

## T4 Rulings (recorded per the standing "TUI best practice + spec as authority" mandate)

1. **`/model` builds its own `readModelChoices`.** The name in spec §3.7 is the OLD TUI's function, and that TUI is deleted — there is nothing to import. talon writes it from the live seam: `llm.listProviders() × llm.listModels(provider) × llm.resolveModelInfo(provider, model)`, flattened, with **the current target appended even when the catalog omits it** (a hand-configured model must not vanish from its own selector). Switching is `installModelSelection(agent.ctx, ref)` installed ONCE per bind; afterwards `ref.current = {provider, model, reasoningEffort}` takes effect on the next step (verified: `core/agent/src/model-selection.ts` — prompt assembly snapshots the selection, so a switch mid-step lands on the following step by design, never splitting one). `reasoningEffort` options come from `resolveModelInfo().reasoning.efforts`, never hard-coded; Shift+Tab cycles the highlighted row's effort.
2. **`@file` COMPOSES `@deepseek-ai/dsh-file-reference-local` rather than copying it.** The spec says "WorkspaceFileSearch 照抄: 有界 BFS / tool-result 失效 / 引号语法 / 控制符防御" — but all four already exist, tested, in that package, and it is simply **not composed by `dsh-base`** (verified against `packages/bundle/base/cordis.patch.yml`). talon adds the row to `cordis.patch.yml` exactly as it already does for `tool-ask-user` and `session-projection-cache`, then consumes `ctx.fileReferences.list(agent, query, signal)` and the re-exported `activeAtToken` / `formatFileMention` grammar. Composing beats copying: the bounded traversal, the invalidation and the grammar stay one implementation shared with the web client, and a dsh-side fix reaches talon for free. The service is optional at runtime — an absent `ctx.fileReferences` disables `@file` completion and nothing else.
3. **`@session` has no dsh service and needs none.** It reuses T2's own `buildResumeCandidates` (the title ladder, the concurrency-bounded worker pool, the activity metadata) and offers `id` + title as prompt text. Same law as `@file`: text, never content.
4. **ONE completion provider owns the composer.** pi-tui allows a single `AutocompleteProvider`, and the archaeology's "at most one popup" convention is the same rule. `createCompletionProvider` dispatches on the active token — `/` at the line start → commands (T2's existing provider, unchanged), `@` → files, `@@` → sessions — so the three sources cannot fight for the popup.
5. **OSC 0 title is sanitized, and the sanitizer is `displayText` plus a length cap.** The title can carry model output (the session title), so it takes the same neutralization every rendered string takes, then collapses newlines and cuts to a bounded length. The title is set on bind and on `session/title`; it is restored on teardown.
6. **OSC 9 notifies only while the terminal is UNFOCUSED, and talon tracks focus itself.** pi-tui exposes no focus state (no DEC 1004 in `terminal.js`), so the controller enables focus reporting (`\x1b[?1004h`), reads `\x1b[I` / `\x1b[O` off the input listener it already owns, and disables it on teardown. A terminal that ignores 1004 sends nothing: talon then treats itself as unfocused (notifying is the safe failure — a missed notification is worse than a redundant one), and stops as soon as a focus-in ever arrives. Notifications fire on turn end only, never per chunk.
7. **Image paste is an EXPLICIT shortcut reading the system clipboard, and it is optional by construction.** Bracketed paste of text is pi-tui's already (`insertTextAtCursor` + the paste-marker expansion `getExpandedText()`), so v1's text path is wiring, not code. For images, the parent archaeology explicitly parks the feature ("v1 只做终端原生粘贴…图片粘贴…不是 MVP 必需", `dsh-tui-module-plan.md` §E2) while spec §8 lists it; the spec wins, but the implementation must fail SOFT: a platform read command (`pbpaste`-family) that is absent, fails, or returns no image leaves a plain notice and the composer untouched. Storage is `ctx.attachments.saveImages()`; an absent attachment store disables the shortcut.
8. **`/agents` reads `ctx.subagents.listDescendants(rootId)`** — depth/label/activity/diagnostic come ready-made (`subagent/lib/types/list-children.d.ts`), so the panel renders a tree and never parses a descriptor itself. `diagnostic` rows render as dim reasons, not as errors: a corrupt child is a fact about the log, not a talon failure.
9. **Workflow cards are transcript cells built from the FOUR durable `tool-workflow/*` events**, keyed by `runId`: `run-start` opens the card, `agent-start`/`agent-end` fill and settle its members (keyed by `seq`), `run-end` settles the run. Identical live and on replay, like every other cell. A `subagent/start|end` pair drives only the footer badge (live, ephemeral) — never a cell, so replayed history cannot invent a running subagent (the compaction-indicator law, ruling 7 of T3).
10. **Settings persist PREFERENCE, never state.** `ctx.settings?.register(settingsNamespace('talon'), schema)` with `{get, watch, update}`; an absent service falls back to plain defaults and everything still works. What persists: the color scheme (`dark`/`light`), and whether notifications are enabled. What must NEVER persist, restating §3.10: Ctrl+O visibility, Ctrl+R reasoning, the queued badge, the glyph phase, panel state — all session-scoped UI state.
11. **Windows is made CORRECT here and VERIFIED elsewhere.** Every path operation goes through `node:path` (never a hard-coded `/`), `~`-abbreviation compares case-insensitively on `win32` and refuses to abbreviate across drives, and the git-branch read uses `join`. The pure functions get Windows-shaped inputs in tests on every platform. What this plan CANNOT do is run the terminal snapshot leg on Windows — that needs a Windows runner, and the acceptance line stays open until one runs it. Recorded, not papered over.

### Task 1: `/model` selector

**Files:** Create `src/backend/models.ts`, `src/ui/panels/model-panel.ts`. Modify `src/app/controller.ts`, `src/backend/commands.ts`, tests, checkpoint `model-selector`.

`readModelChoices(llm, current)` — flatten `listProviders × listModels`, resolve each route's info for its context window and efforts, append the current target when the catalog omits it (ruling 1). `ModelPanel` — SelectList + fuzzy filter (the ResumePanel precedent), Shift+Tab cycles the highlighted row's effort from `reasoning.efforts`, Esc clears the filter before closing. `/model` opens it; picking sets `ref.current` and appends a local notice.

**The panel test caught a real bug worth recording:** the row LABEL carries the chosen effort, and SelectList items are constructor-only, so cycling an effort has to rebuild the list — and a naive rebuild reset the highlight to row 0, which meant the next Enter would have selected a **different model than the one the user was looking at**. `build(keep?)` now restores the highlight for an effort cycle and deliberately does NOT for a query change (a new filter should re-land on the top row, the way every filtered list does). Both halves are pinned.

- [x] Steps: failing tests (flatten + current-target append; a provider whose `listModels` rejects is skipped, not fatal; effort cycling only where efforts exist; selection writes `ref.current` and the NEXT step sees it) → implement → checkpoint → gate. Commit: `feat: /model selector — live catalog, effort cycling, next-step switch (spec §3.7)`

### Task 2: `@file` completion

**Files:** Modify `cordis.patch.yml`, `src/ui/composer/slash-provider.ts` → generalize into `src/ui/composer/completion.ts`, `src/app/controller.ts`, tests.

Compose the `file-reference-local` row (ruling 2). One provider dispatches by active token (ruling 4): `activeAtToken` decides whether `@` completion is live, `ctx.fileReferences.list` supplies candidates, `formatFileMention` formats the insertion. A `tool/result` invalidates the index (the workspace changed under the user). Absent service → the `@` path is inert and `/` completion is unaffected.

**Composing paid for itself immediately: the tool-result invalidation needed NO talon code.** `LocalFileReferenceService` already listens for `session/event` and invalidates the agent's index on `tool/result` (`file-reference-local/src/index.ts:97-100`) — one of the four behaviours the spec asked talon to reproduce, obtained by wiring rather than writing. The other three (bounded traversal, quote grammar, control-character defense) come from the same package: `formatFileMention` REFUSES a path carrying controls or a quote, and talon drops such a candidate rather than escaping it — an escaped path inserted into the user's own prompt would be a lie about the file's name.

`createSlashProvider` became `createCompletionProvider`; T2's `/` test block carried over byte-exact, which is what proves the `/` branch did not change when `@` joined it.

- [x] Steps: failing tests (token detection incl. an email's `@` NOT triggering; quoted paths; directory descent keeps the quote open; candidates are escaped before display; tool-result invalidation; absent service) → implement → gate. Commit: `feat: @file completion over the composed file-reference service (spec §8 T4)`

### Task 3: `@session` completion

**Files:** Modify `src/ui/composer/completion.ts`, `src/backend/sessions.ts`, tests, checkpoint `at-completion`.

`@@` offers recent sessions by title through T2's existing candidate builder (ruling 3), inserting `@@<id>` as prompt text. Shares the one provider and the one popup.

**The discriminator falls out of the grammar for free:** `activeAtToken` reads `@@query` as ONE `@` token whose query itself begins with `@`, so the session branch needs no second parser — a leading `@` in the query is the switch, and a single `@` stays on the file branch. **Caching is load-bearing, not an optimization:** pi-tui re-queries the provider on every keystroke and enumerating sessions is real I/O through the title ladder, so the listing is built once per interaction and rebuilt only after a rebind, where `/clear` or `/resume` can genuinely have changed the set. Both facts are pinned by test (one keystroke run → one enumeration).

- [x] Steps: failing tests (trigger only on `@@`; title ladder reused; hostile titles escaped; no session service → inert) → implement → checkpoint → gate. Commit: `feat: @session completion reusing the T2 title ladder (spec §8 T4)`

### Task 4: OSC 0 terminal title

**Files:** Create `src/ui/terminal-title.ts`. Modify `src/app/controller.ts`, `src/backend/{translate,app-events}.ts`, tests.

`session/title` → an AppEvent the controller consumes for the title only (never a cell). Sanitize with `displayText` + newline collapse + a length cap (ruling 5); set on bind, on title change, and restore on teardown.

**The recorded-replay golden proves the whole path on a real log**: regenerating it after this task turned its header into `title "Hi"` — the actual title that session carried. Sanitization is `displayText` (controls AND the BIDI set T3 added) then a newline/whitespace collapse then a length cap, because a title bar interprets escapes exactly like the screen and an unbounded title is a way to push the real one out of view. An empty title answers the default rather than blanking the bar, and a rebind resets — the new session names itself on its own `session/title`.
